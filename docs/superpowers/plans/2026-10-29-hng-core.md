# HNG P1 scheduling core implementation plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task by task. Steps use checkbox syntax for tracking.

**Goal:** Implement the hardware-free P1 scheduling core and connect it to all DPDS host layouts on `hng/core` in both forks.

**Architecture:** One scheduler per ingress direction owns one shared FIFO C/Q. Service completion releases Q before fixed propagation and seeded late selection feed two monotone FIFOs. Merge heads by `(deadline, ingress_seq)`. Keep upstream APIs and attribution; expose the HNG scheduler separately through the generated C header.

**Tech Stack:** Rust, existing serde/cbindgen; C/DPDK 26.03, Meson/Ninja, null PMD. No new runtime dependencies.

**Spec:** research records `research/agents/tasks/2026-10-29-implementation worker.md`, the 19:10/19:35 decisions and P0 report; reconcile with `origin/hng/design:docs/HNG-DESIGN.md` when published.

## Global constraints

- Each direction has one C and finite byte Q shared by every flow, before propagation delay.
- Q includes the packet in service and releases its bytes at service completion.
- `deadline = service_finish + t + I*delta`; integer time; stable equal-deadline ordering.
- Seeded selection is per packet and reproducible; direction seeds and byte conventions are recorded.
- Count Q, delay-storage, invalid input, NIC/mempool and handoff/TX drops separately.
- Only user-local tools, synthetic PMDs, and fork branches. Never access the testbed or push main.
- Preserve Apache-2.0 and original authors. Upstream legacy API remains available.

## Review focus

- Equality at Q capacity and at service completion; full packets remain charged while in service.
- Same-time arrivals, mixed sizes, fractional-nanosecond serialization, long uptime and overflow.
- Seed replay, p=0/1, equal deadlines across ordinary/late heads; ordinary and late subsequences preserve order.
- Storage exhaustion and invalid input do not reserve Q or transfer pointer ownership; all accepted pointers drain exactly once.
- Both directions, all 2/3/4-lcore layouts, sparse port IDs, shutdown draining and TX/ring loss accounting.
